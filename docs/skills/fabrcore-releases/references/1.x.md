# FabrCore 1.x upgrade boundaries

## 1.6 baseline

`v1.6.0` aliases `v1.5.0` with no tree changes. The 1.6 patches change remote administration:

| Version | Configuration change |
| --- | --- |
| 1.6.1 | `CloudServer:Connect` becomes `CloudServer:RemoteAdministration`; `FabrCore:HostUrl` is the administration execution target |
| 1.6.2 | Move to `FabrCore:RemoteAdministration`; Cloud Server API key also authenticates the local administration hop |
| 1.6.3 | Use `FabrCore:RemoteAdministration:Enabled`, replacing singular `Enable` |

For a 1.6.3 baseline, remove obsolete nested shapes. Remote administration requires
`FabrCore:CloudServer:Enabled=true`, its API key, and an absolute `FabrCore:HostUrl`.
Keep credentials in secrets. Validate configuration retrieval and the authenticated remote hop.
Cloud Server is optional; do not enable it to upgrade a local-only deployment.

In 1.x, SQL hosting needs `FabrCore.Host.SqlServer`, Azure needs `FabrCore.Host.AzureStorage`,
and Memory/GraphRAG use separate service packages. Keep these only when stopping on 1.x;
2.0 consolidates SQL and knowledge packages.

## 1.6 to 1.7

### 1.7.0 required changes for affected consumers

- **WebSocket:** raw `AgentMessage`/`EventMessage` frames are removed. Use
  `FabrCore.Client.WebSocket` or implement the `fabrcore.v2` subprotocol with an authenticated
  one-time ticket and `hello`. Remove `MessageType: "command"`, `createagent`, implicit delivery
  mode selection, and `DropOldest` queue behavior. Provision agents/blueprints through HTTP.
  Test reconnect, acknowledgements, replay, duplicate delivery, and gaps. Principal selection via
  `x-fabrcore-userhandle`/`userhandle` is disabled outside explicit development compatibility.
- **Surface:** move `{ "swarm": { "squads": [...] } }` to `{ "squads": [...] }` in stored
  and shipped blueprints. Replace `squadType: "swarm"` with `orchestrator` for one-hop routing
  or `task` for multi-step work. Replace `FabrCore.Surface.Ai.Swarm`, `SurfaceSwarm*`, Swarm
  options/services, and `SurfaceTaskRunnerAgent` with the appropriate
  `FabrCore.Surface.Ai.Squads`, `.Ai.Tasks`, `ISurfaceSquadService`, and `SurfaceTaskHarnessAgent`.
- **Compaction:** replace ignored `MidTurnCompactionEnabled`/`_MidTurnCompactionEnabled` with
  `ContextCompactionEnabled`/`_ContextCompactionEnabled`. Supply both `ContextWindowTokens`
  and `MaxOutputTokens`; missing metadata reports `context:unconfigured`. Remove use of
  `FabrCoreRunStoppedException.CheckpointCount`, its constructor argument, and
  `_fabrcore_checkpoint_count`. Run safety no longer compacts persisted history mid-turn.
- **Harness users:** native modes default to planning. Send
  `AgentMessage.Args["_plan-mode"] = "false"` to execute, or `_HarnessMode=false` to retain the
  mode-independent todo loop. Run through `FabrCoreHarnessResult.RunAsync` so snapshots persist.
  Restored todos/delegation records do not resume previously running remote work; it becomes lost.
  Harness adoption is optional for ordinary agents. Respect upstream experimental API diagnostics.
- Align direct Agent Framework dependencies with 1.16.0 and rebuild.

### 1.7.1

- Remote `/fabrcoreapi/ModelConfig/*` requests require a `FabrCoreAdmin` bearer credential.
  Configure `FabrCore:AdminAuthentication:ApiKey` for `FabrCoreHostApiClient` and test remote
  access. In-process Host agents resolve through `IFabrCoreModelConfigurationResolver` without
  a loopback credential. Remove application workarounds that depend on anonymous model access.
- Application and referenced dependency assemblies load before registry discovery.
  `AdditionalAssemblies` remains useful for dynamic assemblies; `RegistryAssemblies` restricts
  discovery to an exact set. Verify published agent/plugin/tool discovery before removing overrides.
- `MissingPlanModeBehavior` allows choosing behavior when `_plan-mode` is absent; planning remains
  the compatibility default. Test callers that omit the argument.
- Cloud Server long-poll isolation and Copilot typing-timer fixes need no new feature opt-in.

### 1.7.2

Teams proactive delivery, Copilot streaming, and Surface chat styling receive fixes. Re-test
proactive delivery with an established channel conversation and check streaming completion.
No additional package-layout or application schema migration is introduced by this patch.

## 1.7 to 1.8

### 1.8.0

- A2A protocol hosting is built into `FabrCore.Host` and disabled by default. Existing applications
  need not enable it. To adopt it, configure `FabrCore:A2A:Enabled`, published agents, caller
  authentication, and principal mapping in application configuration. Test cards, authorization,
  send/stream, cancellation, and ownership against the configured endpoints.
- Remove `FabrCore.Sdk.A2AAgentProxy` and `A2AAgentSession` usage. These old in-process adapters
  were not A2A protocol implementations. Use `FabrCoreBackgroundAgent` for delegation or Host
  A2A endpoints for protocol integration; this is not a mechanical type rename.
- Custom A2A resolvers use
  `ValueTask<string?> ResolvePrincipalHandleAsync(HttpContext, A2AExposedAgent, string, CancellationToken)`.
  `DescribeCaller` remains synchronous. This also applies when migrating an early integration
  built against the synchronous API before the tagged release.
- `FabrCore.Host.Testing` is an optional testing dependency with `FabrCoreA2ATestHost`; do not add
  it to production projects merely to upgrade.
- Cloud-managed settings introduce bootstrap/provider/policy behavior. For Cloud Server users,
  check effective values, restart-required settings, readiness, and last-known-good behavior.

### 1.8.1

The tagged diff from 1.8.0 changes the harness test suite (quarantining a flaky completion test),
with no runtime tree changes. It requires no additional application migration.
