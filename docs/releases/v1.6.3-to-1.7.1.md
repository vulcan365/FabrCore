# FabrCore v1.7.1

FabrCore v1.7.1 is a substantial runtime and developer-platform release focused on dependable
long-running agents, production-ready real-time connectivity, and simpler multi-agent
orchestration. These notes cover the complete public release gap from v1.6.3 to v1.7.1.

## Highlights

- Introduced the FabrCore Agent Harness for durable, model-managed work: todo lists, bounded
  iteration loops, plan and execute modes, background delegation, and session recovery across
  Orleans grain deactivation.
- Added a two-layer compaction ladder that bounds each model call without rewriting history, then
  compacts persisted conversation history between turns.
- Delivered WebSocket protocol v2 and the new `FabrCore.Client.WebSocket` NuGet package, with
  authenticated tickets, reconnect support, ordered durable delivery, replay, acknowledgements,
  and gap detection.
- Added immutable, versioned, per-principal Harness Skills backed by FabrCore typed storage and
  managed through authenticated administration APIs.
- Replaced the Surface Swarm implementation with simpler blueprint-defined `orchestrator` and
  `task` squads built on the new Harness primitives.

## Agent Harness and long-running work

- Added `CreateFabrCoreHarnessAgent` for `FabrCoreAgentProxy` agents and
  `AsFabrCoreHarnessAgent` for direct `IChatClient` composition.
- Added model-managed todo execution, bounded completion loops, completion-marker and AI-judge
  modes, and explicit reporting when work remains unfinished.
- Added durable `plan` and `execute` modes, including per-message `_plan-mode` selection and
  configurable behavior when a message omits the mode.
- Added background-agent rosters with health checks, collision-safe delegate names, registry
  descriptions and capabilities, delegation timeouts, and ACL-governed agent messaging.
- Added per-thread Harness snapshots for todo state and delegation records. Invalid or incompatible
  snapshots fail safely by starting a fresh session, while interrupted in-flight delegations are
  reported as lost rather than silently treated as complete.
- Added bounded private internal specialists through `CreateInternalAgentAsync`, with explicit
  read/compute/effect risk classification, tool resolution controls, per-specialist and per-proxy
  execution budgets, child LLM attribution, lifecycle monitoring, and activation-scoped cleanup.
- Added reference documentation, templates, sample blueprints, and extensive automated coverage
  for Harness configuration, durability, delegation, internal specialists, and orchestration.

## Context and history compaction

- Added `ContextCompaction`, `ContextCompactionConfig`, and `CompactionLadder` for reversible,
  per-call context reduction during tool loops.
- The default ladder now evicts old tool results at 50% of the input budget, truncates old message
  groups at 80%, runs persisted history compaction at 87% of the model context window, applies a
  projection fuse at 90%, and stops a run that still exceeds the configured model window.
- Added model settings `ContextCompactionEnabled`, `ContextEvictThreshold`, and
  `ContextTruncateThreshold`, plus matching `_Context*` agent argument overrides.
- History compaction now runs only before or after a turn. It no longer rewrites persisted history
  in the middle of an active tool loop.
- Added resolved-ladder diagnostics and `compaction.history.started`,
  `compaction.history.completed`, and `compaction.history.failed` monitor events.

## WebSocket v2 and the typed client

- Added one-time authenticated WebSocket tickets, the required `fabrcore.v2` subprotocol, and an
  explicit connection handshake.
- Added typed operation and delivery envelopes instead of raw `AgentMessage` frames.
- Added durable, ordered, at-least-once delivery with replay after reconnect, explicit
  acknowledgements, checkpoint storage, gap detection, per-principal delivery limits, and inactive
  client cleanup.
- Added the reconnecting `IFabrCoreWebSocketClient` implementation in the new
  `FabrCore.Client.WebSocket` package, including send-and-receive, event delivery, cancellation,
  acknowledgment, and resynchronization support.
- Added authentication, protocol, operation-dispatch, delivery-grain, client-contract, and
  end-to-end test coverage.

Agent creation and blueprint provisioning remain HTTP-only operations.

## Versioned Harness Skills

- Added immutable skill references using exact `name@version` identities and `_HarnessSkills`
  agent configuration.
- Added principal-scoped publishing, listing, retrieval, and deletion APIs under
  `/fabrcoreapi/admin/v1/principals/{principalId}/skills`.
- Added corresponding typed SDK methods:
  `ListHarnessSkillsAsync`, `GetHarnessSkillAsync`, `PublishHarnessSkillAsync`, and
  `DeleteHarnessSkillAsync`.
- Added ZIP-based publication with strict path, encoding, size, frontmatter, content-type, and
  integrity validation. Executables, scripts, symbolic links, traversal paths, and unsupported
  resource types are rejected.
- Skill manifests and textual resources are normalized into typed FabrCore storage with no TTL;
  resources are loaded lazily and integrity-checked at runtime.
- Skill administration requires the `FabrCoreAdmin` policy and records audited outcomes without
  writing skill content to the audit log.

## Surface squads

- Removed the production-problematic Swarm runtime and replaced it with the smaller
  `FabrCore.Surface.Ai.Squads` model.
- Added blueprint-defined `orchestrator` squads for one-hop routing and `task` squads for
  Harness-driven multi-step coordination.
- Added `SurfaceTaskHarnessAgent`, which manages model-owned todos, delegates concurrently to
  executor members, consults subject-matter-expert members, and continues until work is complete or
  the configured iteration limit is reached.
- Simplified the blueprint schema from nested `swarm.squads` configuration to the top-level
  `squads` extension.
- Updated Surface, the sample application, documentation, blueprints, and tests to use the new
  squad model.

## Runtime, configuration, and security improvements

- `AddFabrCoreServer` and `AddFabrCoreServices` now load the application assembly and referenced
  FabrCore dependencies before agent, plugin, and tool discovery. Most applications no longer need
  to populate `AdditionalAssemblies`; it remains available for dynamically selected assemblies
  outside the application dependency graph.
- Added `RegistryAssemblies` as an optional exact discovery scope while preserving process-wide
  discovery as the default.
- Added `IFabrCoreModelConfigurationResolver`. In-process Host agents now resolve model settings and
  provider credentials directly from the active local, Cloud Server, or custom configuration store
  instead of making a loopback HTTP request.
- Protected the model-configuration and API-key endpoints with the `FabrCoreAdmin` policy. Remote
  SDK clients can authenticate with `FabrCore:AdminAuthentication:ApiKey` and now receive explicit
  diagnostics for authorization failures, redirects, non-JSON login pages, and malformed results.
- Isolated the Cloud Server `/fabrcore-cloud/v2/connect` long poll from application-wide HTTP
  resilience handlers. Polling now uses a dedicated timeout, sequential transient retries, one
  active poll per Host client, clean shutdown cancellation, and structured terminal outcomes.
- Fixed Microsoft 365 Copilot streaming so the independent typing timer stops before the final
  success or error activity, preventing a late typing indicator after the response completes.

## Breaking changes and upgrade guidance

### WebSocket clients

The legacy raw-`AgentMessage` WebSocket contract has been removed. `/ws` now requires the
`fabrcore.v2` subprotocol, a one-time authenticated ticket, and a `hello` frame. Raw
`AgentMessage`/`EventMessage` frames, `MessageType: "command"`, `createagent`, delivery-mode
inference, and `DropOldest` outbound queues are no longer supported. Migrate clients to
`FabrCore.Client.WebSocket` or implement the v2 protocol directly.

Principal selection through `x-fabrcore-userhandle` or `userhandle` is disabled except when the
explicit development-only compatibility option is enabled.

### Surface blueprints and APIs

Migrate blueprint documents from:

```json
{ "swarm": { "squads": [/* ... */] } }
```

to:

```json
{ "squads": [/* ... */] }
```

Replace `squadType: "swarm"` with `orchestrator` for one-hop routing or `task` for
Harness-driven multi-step work.

The `FabrCore.Surface.Ai.Swarm` namespace, `SurfaceSwarm*` types, Swarm services and options, and
`SurfaceTaskRunnerAgent` were removed. Update integrations to `FabrCore.Surface.Ai.Squads`,
`FabrCore.Surface.Ai.Tasks`, `ISurfaceSquadService`, and `SurfaceTaskHarnessAgent` as appropriate.

### Compaction and run-safety APIs

- `MidTurnCompactionEnabled` and `_MidTurnCompactionEnabled` are retired. The model property remains
  deserializable for configuration compatibility but is obsolete and ignored. Use
  `ContextCompactionEnabled` or `_ContextCompactionEnabled`.
- Configure both `ContextWindowTokens` and `MaxOutputTokens` to enable layer-one context
  compaction. If either value is absent, FabrCore continues without in-run context compaction and
  reports `context:unconfigured` in the ladder diagnostic.
- `FabrCoreRunStoppedException.CheckpointCount`, its constructor parameter, and the
  `_fabrcore_checkpoint_count` response diagnostic were removed because run safety no longer
  performs compaction checkpoints.

### Harness behavior

- Native Harness plan/execute modes are enabled by default. Pass
  `AgentMessage.Args["_plan-mode"] = "false"` for an execution run, or set `_HarnessMode=false` to
  retain the earlier mode-independent todo loop.
- Harness APIs inherit the Microsoft Agent Framework experimental designation. Execute through
  `FabrCoreHarnessResult.RunAsync`; calling the inner agent directly bypasses FabrCore snapshot
  persistence.
- Snapshot restore preserves todos and delegation records, but work already running in another
  agent cannot be resumed after grain deactivation and is reported as lost.

### Remote model-configuration access

Callers that access `/fabrcoreapi/ModelConfig/*` from another process must now send a valid
`FabrCoreAdmin` bearer credential. Configure `FabrCore:AdminAuthentication:ApiKey` for
`FabrCoreHostApiClient`. In-process Host agents require no loopback credential because they resolve
the active configuration store directly.

## Dependencies

- Updated `Microsoft.Agents.AI` and `Microsoft.Agents.AI.OpenAi` from 1.15.0 to 1.16.0.
- Updated affected test projects to MSTest 4.3.3 and Microsoft.Testing.Extensions.TrxReport 2.3.3.
